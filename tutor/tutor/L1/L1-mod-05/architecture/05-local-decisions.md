## 1. 本层决定（decide_now）

### LCD-001 端内通知的实现归属

- 来源：CT-005 副作用「触发教师端内通知」；F2-5；A-005（首版端内通知，列表/详情可见）；DF-2 步骤 4–6。
- 备选：
  - (a) **通知作为读模型派生条目，由 CMP-READMODEL-PROJECTOR 投影**（采用）：通知条目 = scoring_failed 提交在列表/详情中的可见标记，与其余派生状态同一写路径、同一重放机制。
  - (b) 独立 CMP-NOTIFICATION 子节点：首版无已读/未读、无多渠道需求，单独状态与写路径徒增复杂度；渠道扩展（邮件/IM）为父层暂缓项，届时再评。
  - (c) 查询时临时推导（归 CMP-REVIEW-QUERY）：失败状态推导规则散入读侧，与「消费幂等/去重」语义分离，重建时口径易漂移。
- 后果：通知无独立存储；未来引入已读状态或外部渠道时，需在 CMP-READMODEL-PROJECTOR 上演化或新增子节点（父层暂缓项触发时再评估，不影响父契约）。

### LCD-002 事件消费拓扑

- 来源：CT-005/CT-006/CT-012(自消费)/CT-014 四个消费点（父 04 组件接口卡）。
- 备选：
  - (a) **按状态所有者分散消费**（采用）：CMP-READMODEL-PROJECTOR 消费 CT-005/CT-006/CT-012(自)（读模型写路径单点）；CMP-RETENTION-GOVERNANCE 消费 CT-014（DeletionBatch 状态机转移）。消费幂等键与状态所有者同处，事务边界清晰。
  - (b) 统一事件接入层子节点再分发：多一层间接，且 CT-014 与投影的消费语义（去重键、事务边界）本就不同，统一层只增复杂度。
  - (c) 每个契约一个消费子节点：过细，CT-005/CT-006 投影逻辑高度同源。
- 后果：新增 MOD-05 消费事件时按「状态归谁」落到对应子节点；不改变父 Outbox 投递机制。

### LCD-003 ReviewRecord 创建路径

- 来源：DF-1 步骤 11「创建复核记录」（CT-005 副作用）；ReviewRecord 单写方原则（父 03 本地事务边界）。
- 备选：
  - (a) **CMP-READMODEL-PROJECTOR 经 M05-IC-01 调用 CMP-REVIEW-COMMAND 创建**（采用）：ReviewRecord 全部写入（教师命令与系统创建）收敛于一个子节点，不变量单点守护。
  - (b) 投影子节点直接写 ReviewRecord：聚合出现两个写方，禁伪造/留痕不变量需双份实现。
  - (c) 复核记录延迟到教师首次打开详情时创建：CT-008 前无记录可应答「原始等级」字段，且创建动作混入读路径。
- 后果：M05-IC-01 按 submission_id 幂等；CT-005 重复投递不产重复记录。

### LCD-004 展示视图数据源

- 来源：CT-009 区块（项目结果、过程摘要、评分、批注、缺失标记）；A-003（摘要引用评估产出）；父 03「生成时快照」。
- 备选：
  - (a) **生成时从教师读模型装配并快照**（采用）：读模型已含评估结果（CT-005 投影）与复核数据（M05-IC-05 投影）；符合「快照不实时更新」语义。
  - (b) 生成时实时跨模块读取 MOD-02/MOD-04：引入父包不存在的同步跨模块读契约，越界（须 return_to_parent，无产品收益）。
  - (c) 由 MOD-04 预生成展示区块随 CT-005 下发：改变 CT-005 字段语义，越界。
- 后果：生成质量依赖读模型投影完成度（秒级最终一致）；教师刚调整即生成时读模型可能短暂滞后——由 CT-009 幂等再生成吸收（重新生成返回最新快照，F4-1 语义允许）。

### LCD-005 删除后的数据处置与重放守卫

- 来源：CT-012 自消费「模块内清除读模型」；AC-NFR-004-01 pass_rule「删除后教师端不可读」；父 03「读模型可事件重放全量重建」；NFR-004「评分记录」一并删除。父包未显式规定 ReviewRecord/PresentationView 本体处置 → 影响不出本节点（两聚合均无外读方），按规则本层可定。
- 备选：
  - (a) **自消费清除读模型，并擦除对应 ReviewRecord/PresentationView 内容；投影/重放经 M05-IC-06(b) 过滤已完成批次的 submission_id（P-重放守卫）**（采用）：同时满足「评分记录删除」与「重建不复活已删数据」；审计记录（范围/操作者/时间）不受影响。
  - (b) 仅清读模型、保留两聚合本体：教师端不可读可满足，但 NFR-004「评分记录保存 1 年后删除」落空，且重放复活风险仍需守卫，保留本体无业务收益。
  - (c) 连同事务性物理删除审计关联键：审计记录须含范围且永久留存，不可弱化（父不变量）。
- 后果：DeletionBatch 的完成集合成为投影过滤的真源；擦除为内容级（保留行位/审计关联），详细擦除粒度为 implementation_detail。

### LCD-006 课程范围授权数据本地持有

- 来源：FR-009 课程范围授权 + 访问拒绝记录；CT-007~CT-011 FORBIDDEN 语义；A-001（账号由管理员/课程创建流程发放，教师身份不构成新领域边界）。父包未给出授权数据的归属模块 → 影响不出本节点（无其他模块读写该数据），本层可定。
- 备选：
  - (a) **MOD-05 本地持有 TeacherAccessGrant（教师-课程授权关系），CMP-ACCESS-GATE 鉴权使用**（采用）：与 AccessDeniedLogged 同属 BC-REVIEW 安全面；发放走管理流程（A-001），本层不实现自助管理界面。
  - (b) 经 FLOW-011 扩展读取 MOD-03 课程数据推导授权：违反 FLOW-011「仅课程结束时间」的父层限定（越界）；且 Course 聚合本就无教师授权数据（父 03 所有权表）。
  - (c) 网关外置统一授权组件：父包无此组件，等于新增平台能力（越界）。
- 后果：授权数据为 MOD-05 内部状态（ST-TEACHER-ACCESS-GRANT）；若未来教师自助/多角色需求出现，回父层评估（Q-04 已登记）。
