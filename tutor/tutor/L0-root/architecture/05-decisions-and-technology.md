### 决策理由

- **KD-001 外部模型 API**：租赁服务器无 GPU，自托管模型成本与运维能力要求超出团队；外部 API 使 10 分钟评分目标（NFR-003）易于达成。代价：材料数据出境至供应商，由 ACL 材料最小化与供应商协议控制（PRD 风险节：材料含个人信息/第三方代码）。
- **KD-002 同组服务共部署**:100 名学生、30 并发提交（NFR-001/002）单机可承载；独立托管服务（对象存储 + 托管 MQ）对该规模明显过剩且增加运维成本。Outbox 表保证事件不丢且无需引入消息中间件。
- **KD-003 基础级运维**：与单课程规模、租赁成本、团队运维能力匹配；加密与每日备份是含学生数据系统的底线；标准级（跨地域副本）的收益不抵成本。
- **KD-004 500MB / 200GB**：代码项目 + 截图 + 对话记录的单次量级远低于 500MB，整学期 100 名学生总量在 200GB 内（A-006)；白名单降低安全风险。
- **KD-005 令牌+幂等键+分片续传**：满足 AC-REQ-001-01（断网保留本地任务、恢复重传）、NFR-002(30 并发不产生重复提交）；令牌支持访问审计（材料含个人信息）。

## 技术组件选择

| 组件 | 选择 | 来源驱动 |
|---|---|---|
| 服务端形态 | 模块化应用：MOD-02/03/05 同部署单元，MOD-04 独立部署单元（见 06) | 评估耗时与接收负载特征不同（M6);KD-002 |
| 结构化存储 | 单一关系型数据库（产品选型 defer_to_detail_design，要求事务 + 备份） | M2 本地事务边界；KD-002 |
| 材料文件存储 | 服务器本地磁盘，存储加密 | KD-002、KD-003 |
| 异步任务/事件 | 数据库持久化任务表 + Outbox 表 + 后台投递器 | REQ-007 异步评分；KD-002 |
| 教师前端 | 服务端渲染或 SPA 网页（defer_to_detail_design) | REQ-009/010 |
| 插件 | Codex Plugin 机制内实现，本地待上传队列 | REQ-001~004;A-007 |
| 模型接入 | 供应商 API 客户端封装于 MOD-04 ACL | KD-001 |

## 不采用方案

| 方案 | 不采用原因 |
|---|---|
| 微服务全量拆分 | 5 个 Module 中 3 个无独立扩缩/发布需求；团队运维能力优先（M6 规则） |
| 消息中间件（Kafka/RabbitMQ) | 事件量小（百级学生）,Outbox 已满足；避免无来源组件 |
| 工作流引擎 | 评分流程为单任务一次重试，复杂度不需要 |
| 对象存储/托管服务 | KD-002 已决策同组共部署 |
| 缓存/搜索引擎 | NFR-001 规模下事件派生读模型已满足查询 |
| 分布式事务 | 无跨 Module 强一致业务要求（M2) |
| 服务器内自托管模型 | KD-001 已决策外部 API |
