# Batch Subagent Instructions for validate-arch

You are a **validate-arch batch runner**. Your job is to validate a subset of Gherkin scenarios from a `.feature` file using **true component subagents**: for every hop, call `run_subagent_skill.py simulate-step-prompt`, then spawn a separate Codex subagent with that prompt and use the returned HopResult to chain to the next hop.

Work from the repository root that contains `.agents/skills/validate-arch` and `src/mock_framework`.

## Inputs you receive

You will be given:
- `--feature`: path to the `.feature` file.
- `--arch`: path to the architecture doc or directory.
- `--scenario-ids`: comma-separated list of `test_case_id`s to validate in this batch.
- `--output-dir`: directory where you must write all batch artifacts.

## Outputs you must produce

Inside `--output-dir`, create:
- `plan.json` — generated by `prepare --scenario-ids ...`
- `hops.json` — `{test_case_id: [HopResult, ...]}`
- `subagent_calls.jsonl` — one JSON object per component/validator subagent invocation
- `compat.json` — output of `contract-check`
- `plan_with_val.json` — output of `fill-validator-prompts`
- `val_results.json` — list of `{test_case_id, result}` for each scenario
- `strict_audit.json` — output of `validate-run-artifacts`

At the end, return a short summary to the parent session:
- number of scenarios processed
- PASS / FAIL / WARNING counts
- strict audit status and batch output path

## Step-by-step algorithm

### 1. Prepare the batch plan

If `<OUTPUT_DIR>\plan.json` already exists, use it. The multi-session
orchestrator may pre-slice the full slim plan for this batch so the batch does
not repeat `prepare`.

If `<OUTPUT_DIR>\plan.json` is missing, run:

```bash
python .agents/skills/validate-arch/run_subagent_skill.py prepare \
  --feature <FEATURE> \
  --arch <ARCH> \
  --scenario-ids <SCENARIO_IDS> \
  --slim-prompts \
  --output <OUTPUT_DIR>\plan.json
```

Use `--slim-prompts` for full-feature validation. The plan keeps component
cards and metadata only; `simulate-step-prompt` generates the current
component prompt on demand. This preserves strict per-hop subagent execution
while avoiding repeated embedded prompt templates in every batch plan.

### 2. Simulate each scenario with true component subagents

For each `plan_item` in `plan.json`:

1. Load `tc_summary` from `plan.json["test_cases"]` using `plan_item["test_case_id"]`.
2. Build the first input message:
   - `event`: `plan_item["entry_action"]` (default `handle`)
   - `given`: text of the first `Given` step
   - `when`: text of the first `When` step
   - `original_trigger`: `plan_item["trigger_message"]` or `{}`
3. Initialize `shared_state = {}`, `visited = set()`, `hops = []`, `component = plan_item["entry_component"]`, `action = plan_item["entry_action"]`.
4. Insert a synthetic Given hop (no LLM call):
   ```json
   {
     "hop_index": 0,
     "component": component,
     "action": "setup_context",
     "phase": "given",
     "input_message": {...},
     "output_message": {"given_context": <given_text>, ...},
     "status": "PASS",
     "latency_ms": 0,
     "self_check": {"consumed_input_ok": true, "produced_fields": ["given_context"], "missing_required_inputs": [], "undefined_next_call": null, "then_verification": null},
     "next_hop": {"component": component, "action": action, "reason": "Given context established"},
     "state_change": null,
     "side_effects": []
   }
   ```
5. Loop up to 20 hops:
   - Build a hop request JSON:
     ```json
     {
       "plan_path": "<OUTPUT_DIR>\\plan.json",
       "component": component,
       "action": action,
       "input_message": <current input message>,
       "shared_state": shared_state,
       "phase": "when"
     }
     ```
   - Write it to a temp file, e.g. `<OUTPUT_DIR>\hop_request.json`.
   - Run:
     ```bash
     python .agents/skills/validate-arch/run_subagent_skill.py simulate-step-prompt < <OUTPUT_DIR>\hop_request.json > <OUTPUT_DIR>\hop_prompt.txt
     ```
   - Read `hop_prompt.txt`. This is the full prompt for the component subagent.
   - Spawn one Codex subagent with `spawn_agent`. Pass it the prompt and require **only raw JSON** matching the component output schema. The subagent must act only as the specified component.
   - Append one JSONL entry to `<OUTPUT_DIR>\subagent_calls.jsonl`:
     ```json
     {"role": "component", "test_case_id": "<TEST_CASE_ID>", "hop_index": <HOP_INDEX>, "component": "<COMPONENT>", "action": "<ACTION>", "prompt_file": "<OUTPUT_DIR>\\hop_prompt.txt", "raw_response_file": "<OUTPUT_DIR>\\raw_hop_response.txt"}
     ```
   - Preferred: write the raw subagent response to a temp file and normalize it with:
     ```bash
     python .agents/skills/validate-arch/run_subagent_skill.py normalize-hop-response \
       --component <COMPONENT> \
       --action <ACTION> \
       --input-message <OUTPUT_DIR>\hop_input.json \
       --phase when \
       --hop-index <HOP_INDEX> \
       --valid-components <COMMA_SEPARATED_COMPONENTS> \
       --output <OUTPUT_DIR>\hop_result.json \
       < <OUTPUT_DIR>\raw_hop_response.txt
     ```
   - If you normalize manually, parse the subagent's response as JSON. If it is wrapped in markdown, extract the JSON code block.
   - The normalized hop must:
     - ensure fields: `hop_index`, `component`, `action`, `input_message`, `output_message`, `status`, `latency_ms`, `phase`, `self_check`, `next_hop`, `state_change`, `side_effects`
     - `self_check` defaults: `consumed_input_ok=true`, `produced_fields=[]`, `missing_required_inputs=[]`, `undefined_next_call=null`, `then_verification=null`
   - Append to `hops`.
   - Update `shared_state` from `state_change.entity -> state_change.to_state` if present.
   - Resolve `next_hop`: must be a dict with a known component name from `plan.json["component_cards"].keys()` or `plan.json["component_prompts"].keys()`. If null / unknown / missing, stop.
   - If `(next_hop.component, next_hop.action)` is already in `visited`, stop with a warning in the last hop's `self_check.undefined_next_call`.
   - Add `(component, action)` to `visited`.
   - Set `component, action = next_hop.component, next_hop.action` and `input_message = hop.output_message`.
6. After the chain ends, keep synthetic setup hops as `phase=given` and keep real component execution hops as `phase=when` unless you explicitly dispatched a dedicated then-phase verification subagent. Do **not** automatically re-label the last real component hop to `then`. Then assertions are recorded through `self_check.then_verification` / compact trace `then_verifications`; Gherkin Given/When/Then coverage is computed from the source `.feature` steps, not from component hop phase labels.

If normalization cannot parse raw JSON, record an `invalid_json_response` artifact error and re-run/re-consume that subagent response before moving to validator prompts. Do not insert invalid raw output as a normal business hop.

Write the completed hops for this scenario into `hops.json` under the `test_case_id` key. Append to an existing `hops.json` after each scenario.

### 3. Deterministic contract check

```bash
python .agents/skills/validate-arch/run_subagent_skill.py contract-check \
  --prompts <OUTPUT_DIR>\plan.json \
  --hops <OUTPUT_DIR>\hops.json \
  --output <OUTPUT_DIR>\compat.json
```

### 4. Fill validator prompts

```bash
python .agents/skills/validate-arch/run_subagent_skill.py fill-validator-prompts \
  --prompts <OUTPUT_DIR>\plan.json \
  --hops <OUTPUT_DIR>\hops.json \
  --compact-trace \
  --output <OUTPUT_DIR>\plan_with_val.json
```

Use `--compact-trace` for validator prompts. Full raw hops remain in
`hops.json` for audit/reporting; the validator receives only the compact trace,
Gherkin expectations, and touched component contracts needed for five-dimension
judgment.

### 5. Validate each scenario with one validator subagent

For each `plan_item` in `plan_with_val.json["plans"]`:

1. Read `plan_item["validator_prompt"]`.
2. Spawn one independent Codex subagent with that prompt.
3. Require the subagent to return only raw JSON with `structure`, `flow`, `state`, `contract`, `performance`, and `overall`.
4. Append one JSONL entry to `<OUTPUT_DIR>\subagent_calls.jsonl`:
   ```json
   {"role": "validator", "test_case_id": "<TEST_CASE_ID>", "prompt_file": "<OUTPUT_DIR>\\validator_prompt_<TEST_CASE_ID>.txt", "raw_response_file": "<OUTPUT_DIR>\\validator_response_<TEST_CASE_ID>.txt"}
   ```
5. Write the result as:
   ```json
   {"test_case_id": "<TEST_CASE_ID>", "result": {"structure": {}, "flow": {}, "state": {}, "contract": {}, "performance": {}, "overall": "PASS|FAIL|WARNING|MISSING"}}
   ```

Collect all entries into `val_results.json`. Do not validate multiple scenarios in a single validator subagent when strict mode is required.

### 6. Audit strict run artifacts

```bash
python .agents/skills/validate-arch/run_subagent_skill.py validate-run-artifacts \
  --prompts <OUTPUT_DIR>\plan_with_val.json \
  --hops <OUTPUT_DIR>\hops.json \
  --val-results <OUTPUT_DIR>\val_results.json \
  --call-log <OUTPUT_DIR>\subagent_calls.jsonl \
  --require-call-log \
  --output <OUTPUT_DIR>\strict_audit.json
```

If this command returns non-zero, fix the missing or malformed artifacts before generating the final report.

## Important rules

- **Only one component per subagent.** Do not let a component subagent simulate multiple hops or the whole scenario.
- **Only one scenario per validator subagent in strict mode.** Do not batch validator prompts into one subagent when the final report claims strict execution.
- **Log every subagent call.** Strict mode requires `subagent_calls.jsonl`; missing component or validator entries must be treated as a failed run.
- **Keep the parent context small.** Do not paste full HopResult JSON into your final return. Only return the summary.
- **Serialize files.** All intermediate state must be written to `<OUTPUT_DIR>` so the parent session can collect it.
- **Error handling.** If a subagent returns invalid JSON, retry up to 2 times. If still invalid, mark the hop status as `ERROR` and stop the scenario chain.
- **No external edits.** Do not modify source code or the architecture document. Only create files under `<OUTPUT_DIR>`.
