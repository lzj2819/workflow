# 父边界规则

这份规则回答一个问题：“设计这个模块内部时，哪些东西可以决定，哪些必须尊重父层？”父层架构是绑定契约；当前层只能细化一个已选定父节点内部，不能重画父架构、部署、契约、所有权或兄弟职责。

## 选择性提取

先使用父包适配器，仅从目标节点及其直接边界提取：稳定身份、职责、排除项、需求追溯；拥有的 API、事件、Schema、副作用、依赖、失败和版本；状态/数据的生命周期、保留、一致性、读写方；直接上下游、兄弟和外部依赖；相关父运行流；已接受 ADR、被拒绝方案、技术/部署决策、风险和已委托项。

无 ID 的旧包必须在清单记录迁移匹配证据，不能将名称匹配作为常规路径。

## 分类

| 分类 | 含义 | 当前层行为 |
|---|---|---|
| `inherited-fixed` | 绑定父决策 | 原样保留；需要修改则返回父层。 |
| `inherited-refinable` | 外部语义固定，内部开放 | 保持外部行为，细化内部。 |
| `delegated` | 父层明确委托 | 当前层决定并记录。 |
| `unresolved` | 父层未决定也未委托 | 仅当影响留在目标节点内时决定，否则返回父层。 |

## 不可协商规则

- 不得将目标节点当作独立系统，除非父层明确委托。
- 不得重选父架构风格、运行时身份、部署模式、数据库、消息平台或技术栈。
- 父层定义为内部节点时，不得创建服务、容器、部署单元或公共运行时边界。
- 不得改名、弱化、移动、升级版本或为父 API/跨节点事件增加必需字段。
- 不得跨父节点或兄弟节点转移状态、公共契约或数据所有权。
- 不设计兄弟节点内部；只作为协作约束引用。
- 按职责、状态、不变量、生命周期、变更原因和交互分解，而非仅按通用分层。

## 返回父层与递归链

当前 PRD 或用户约束改变父职责、排除项、公共契约、数据所有权、依赖方向、ADR、技术、部署或祖先不变量时，创建 `parent-change-request.md`，并在权威分解前停止。

若内部策略可满足压力，采用内部策略并将父层变更记为未接受替代方案。每一层都保持：

```text
当前子节点在选定直接父节点内，直接父节点在祖先架构包内
```

直接父层已与祖先不变量冲突时，标记为继承不一致，不在子层放大。
