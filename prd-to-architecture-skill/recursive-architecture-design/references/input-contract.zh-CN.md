# 输入契约

先用这份清单确认“这次设计谁、资料在哪里、结果放哪里”。本 Skill 细化一个已选定父节点，不重设计整个父层。

## 必需输入

| 字段 | 含义 | 行为 |
|---|---|---|
| `parent_architecture` | 父层架构包根目录 | 只读；按父包适配器识别类型。 |
| `target_node_id` | 要细化的父节点稳定 ID | 分解前必须唯一匹配；仅 `migrate` 模式允许有证据的显示名称匹配。 |
| `current_prd` | 当前节点 PRD | 只用于目标父边界内的需求。 |
| `output_dir` | 当前子包输出目录 | 写入前展示；除非 `revise`，不得覆盖已有包。 |

## 可选输入

| 字段 | 含义 | 行为 |
|---|---|---|
| `parent_prd` | 父节点或系统原始 PRD | 仅当父包无法提供需求追溯时读取。 |
| `mode` | `new`、`revise`、`migrate` | 默认 `new`；`revise` 续写已选包；`migrate` 启用旧包名称匹配。 |
| `existing_architecture` | 已有当前层包 | `revise` 时使用；不得静默覆盖。 |
| `ancestor_architectures` | 直接父层以上的包 | 仅在父包遗漏当前设计所需祖先不变量时提供。 |
| `current_focus` | 当前 PRD 内的窄焦点 | 缩小范围但不丢弃继承约束。 |
| `human_constraints` | 用户偏好或约束 | 与父边界冲突时返回父层。 |

## 解析顺序

1. 相对路径按仓库根目录或当前目录解析。
2. 解析 `mode`、`parent_architecture`、`target_node_id`、`current_prd` 和 `output_dir`。
3. 先运行父包适配器。
4. 写入前展示父包类型、节点匹配证据和输出目录。
5. 必要需求追溯缺失时才读取 `parent_prd`。

## 阻塞条件

父包缺失、不可读或不支持；目标匹配为零或多个；旧包名称匹配无证据；关键父状态/契约/部署/决策不可用；当前 PRD 修改父边界；输出会在非 `revise` 模式覆盖已有包；或信息允许实质不同子架构时，停止设计。
